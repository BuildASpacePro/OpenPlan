╔════════════════════════════════════════════════════════════════════════════════════════╗
║                      CONSTELLATION/CLUSTER DATA FLOW                                     ║
╠════════════════════════════════════════════════════════════════════════════════════════╣
║                                                                                          ║
║  1. DATA INGESTION                                                                     ║
║     └─ Satellites → Database (with name, mission, colour, tle_1, tle_2)               ║
║                                                                                         ║
║  2. CLUSTERING STRATEGY (Multiple approaches)                                          ║
║                                                                                         ║
║     A. API-Based (Primary if available):                                              ║
║        GET /api/clusters/constellation                                                ║
║        └─ Returns pre-computed clusters with full metrics                             ║
║                                                                                         ║
║     B. Client-Side Pattern Matching (Fallback):                                       ║
║        ClusterDetector.jsx extracts cluster keys:                                     ║
║        ├─ CONSTELLATION: "Starlink", "OneWeb", "GPS", "Galileo", etc.               ║
║        ├─ MISSION: "Communication", "Navigation", "Space Station", etc.              ║
║        ├─ ORGANIZATION: "SpaceX", "OneWeb", "CNSA", "International", etc.           ║
║        └─ TECHNICAL: "Large Platform", "Smallsat", "Standard"                       ║
║                                                                                         ║
║  3. METRIC CALCULATION                                                                 ║
║     For each cluster, calculate:                                                      ║
║     ├─ recentEvents: events in last hour (weight: 10)                                ║
║     ├─ dailyEvents: events in last 24h (weight: 2)                                   ║
║     ├─ weeklyEvents: events in last week (weight: 1)                                 ║
║     ├─ criticalEvents: high-priority events (weight: 5)                              ║
║     ├─ activityScore: weighted sum of recent activity                                ║
║     ├─ importanceScore: activity + size + critical events                            ║
║     └─ density: events per satellite                                                  ║
║                                                                                         ║
║  4. TIER SELECTION (Auto-determined)                                                  ║
║     ├─ Tier 1: ≤10 clusters    → GanttChart (individual satellites)                 ║
║     ├─ Tier 2: 11-50 clusters  → ClusterTimelineView (expandable)                   ║
║     └─ Tier 3: 50+ clusters    → ClusterGridView (high-density)                     ║
║                                                                                         ║
║  5. VISUAL ENCODING                                                                    ║
║     ├─ Satellite Color: from satellite.colour field                                  ║
║     ├─ Event Type Color: health→green, payload→blue, AOCS→amber, etc.               ║
║     ├─ Activity Density: gradient red(high) → gray(low)                             ║
║     ├─ Status Indicator: critical→red, active→green, nominal→blue                   ║
║     └─ Event Bar Height: proportional to duration                                    ║
║                                                                                         ║
║  6. INTERACTIVITY                                                                      ║
║     ├─ Hover: Show EventTooltip with full details                                   ║
║     ├─ Click Cluster: Expand to show member details                                 ║
║     ├─ Change Cluster Type: Re-group satellites (constellation/mission/org/tech)    ║
║     ├─ Manual Tier Override: Force Tier 1/2/3 view                                  ║
║     └─ Time Window Selection: hour/day/week/month                                    ║
║                                                                                         ║

║                          KEY OPTIMIZATION STRATEGIES                                    ║
╠════════════════════════════════════════════════════════════════════════════════════════╣
║                                                                                          ║
║  Frontend Performance:                                                                 ║
║  ├─ Lazy loading: Cesium (3D) only loads on demand                                    ║

║  ├─ Memoization: React.memo() on complex components                                   ║
║  ├─ useMemo hooks: Cache expensive calculations                                       ║
║  ├─ useCallback hooks: Memoize event handlers                                         ║
║  └─ Request batching: Combined events + access windows in /api/timeline               ║
║                                                                                         ║
║  Backend Performance:                                                                  ║
║  ├─ DB connection pooling: 20 max connections                                         ║
║  ├─ Cache headers: 5-min cache for static data (/api/satellites, /api/groundstations) ║
║  ├─ No cache headers: Dynamic data (positions, events, clusters)                      ║
║  ├─ Compression: gzip middleware enabled                                              ║
║  ├─ Query optimization: Indexed satellite names, IDs                                  ║
║  ├─ Batch operations: Bulk access window queries                                      ║
║  └─ Async operations: Non-blocking satellite.js calculations                          ║
║                                                                                         ║
║  Data Layer Optimization:                                                              ║
║  ├─ Redis caching: Frequent cluster queries                                           ║
║  ├─ InfluxDB: Time-series storage for efficient range queries                         ║
║  ├─ JSON columns: Store cluster membership as JSON                                    ║
